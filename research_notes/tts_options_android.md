# AnchorReader Android text-to-speech options and narration architecture

Research date: 30 October 2026. Scope: native Android application (`minSdk = 26`, `compileSdk = 35`, `targetSdk = 35`, Kotlin `2.0.21`, AGP `8.8.2`, JVM `17`) inspected at local HEAD `5ed5d0b` (`v1.0.43`; latest public GitHub release `v1.0.46`, published 16 October 2026). Read-only codebase and primary-source investigation only. No application code was modified, no paid API call was executed, and no physical-device CPU latency benchmark or subjective listening study was run. Engineering choices and thresholds below are proposed decisions grounded in primary documentation, Maven/AAR binary inspection, and repository license verification.

## 1. What can AnchorReader fix immediately in `Narrator.kt` with zero new dependencies?

### Takeaway

Upgrade `Narrator.kt`, `MainActivity.kt`, `PlayerScreen.kt`, and `ui/Screens.kt` before adding any neural inference runtime. Enumerate installed `android.intent.action.TTS_SERVICE` engines (`getEngines()`) and offline English `Voice` entries, expose an in-app engine and voice picker with a one-sentence preview, add `ACTION_INSTALL_TTS_DATA` recovery when voice packs are missing, replace single-sentence `QUEUE_FLUSH` synthesis gaps with `synthesizeToFile` `N+1` sentence lookahead into `cacheDir`, and wire `UtteranceProgressListener.onRangeStart` (guaranteed on API 26+) to auto-advance `SentenceDisplay.parts` with a graceful manual fallback. Because Android `TTS_SERVICE` engines run in separate OS processes over Binder IPC, this zero-APK-bloat upgrade also lets power users select external open-source neural TTS engine apps without imposing GPLv3 obligations on AnchorReader.

### Cited Findings

- AnchorReader's `AndroidManifest.xml` already declares `<queries><intent><action android:name="android.intent.action.TTS_SERVICE" /></intent></queries>`, which satisfies Android 11+ (API 30+) package-visibility rules for discovering third-party TTS services on the device (`app/src/main/AndroidManifest.xml`, line 4). [Android TTS package visibility](https://developer.android.com/reference/android/speech/tts/TextToSpeech)
- `Narrator.kt` currently instantiates `TextToSpeech(context.applicationContext)` using only the system default engine, filters `speech.voices` to `it.locale.language == Locale.ENGLISH.language && !it.isNetworkConnectionRequired && !it.features.contains(TextToSpeech.Engine.KEY_FEATURE_NOT_INSTALLED)`, sorts strictly by country (`GB` -> `0`, `US` -> `1`, other -> `2`) and `-it.quality`, and hard-locks `speech.setVoice(voice)` to `firstOrNull()` with no user override (`app/src/main/java/com/anchorreader/Narrator.kt`, lines 60–79).
- Verified against `android-35/android.jar` (`javap`) and Android SDK reference docs, `TextToSpeech` exposes `getEngines(): List<EngineInfo>` and constructor `TextToSpeech(Context, OnInitListener, String enginePackageName)` since API 14, allowing an app to bind any installed TTS engine (for example `com.google.android.tts`, Samsung TTS, or a standalone open-source `TTS_SERVICE` app) without mutating system-wide accessibility defaults. [TextToSpeech API](https://developer.android.com/reference/android/speech/tts/TextToSpeech)
- `android.speech.tts.Voice` defines only five coarse integer quality constants (`QUALITY_VERY_LOW = 100`, `QUALITY_LOW = 200`, `QUALITY_NORMAL = 300`, `QUALITY_HIGH = 400`, `QUALITY_VERY_HIGH = 500`) and latency constants (`LATENCY_VERY_LOW = 100` to `LATENCY_VERY_HIGH = 500`), with no standardized neural-vs-concatenative flag. In Google Speech Recognition & Synthesis (`com.google.android.tts`), multiple offline English voices (including older parametric voices and newer local neural packs such as `en-us-x-iob-local`, `en-us-x-tpf-local`, and `en-gb-x-gba-local`) share identical `quality` integers (`300` or `400`). [Voice API](https://developer.android.com/reference/android/speech/tts/Voice)
- `MainActivity.kt` opens `Intent("com.android.settings.TTS_SETTINGS")` in `openVoiceSettings()` (lines 51–54) and only triggers `narrator.refresh(this)` in `onResume()` when `!state.value.ready && !initializing` (`MainActivity.kt`, line 46; `Narrator.kt`, lines 156–162). Android also provides `TextToSpeech.Engine.ACTION_INSTALL_TTS_DATA` (`android.speech.tts.engine.INSTALL_TTS_DATA`) and `ACTION_CHECK_TTS_DATA` to launch the engine's voice-pack installer directly. [TextToSpeech.Engine API](https://developer.android.com/reference/android/speech/tts/TextToSpeech.Engine)
- `ReaderApp` speaks one sentence per turn via `narrator.speak(text) { ... model.nextSentence() }` using `TextToSpeech.QUEUE_FLUSH` (`MainActivity.kt`, lines 106–115; `Narrator.kt`, lines 116–135), splitting only when a single sentence exceeds `TextToSpeech.getMaxSpeechInputLength()` (`SpeechBuffers.kt`). Every sentence boundary therefore incurs cold synthesis startup latency before audio begins.
- `TextToSpeech.synthesizeToFile(CharSequence text, Bundle params, File file, String utteranceId)` (API 21+) renders speech asynchronously to a WAV file while emitting `UtteranceProgressListener.onStart`, `onDone`, and `onError(utteranceId, errorCode)`. `UtteranceProgressListener.onBeginSynthesis`, `onAudioAvailable`, and `onRangeStart(String utteranceId, int start, int end, int frame)` were added in API 26 (`Android 8.0`), matching AnchorReader's `minSdk = 26` (`app/build.gradle.kts`, line 39). Android documents that `onRangeStart` depends on the engine calling `SynthesisCallback.rangeStart`. [UtteranceProgressListener API](https://developer.android.com/reference/android/speech/tts/UtteranceProgressListener), [SynthesisCallback API](https://developer.android.com/reference/android/speech/tts/SynthesisCallback#rangeStart(int,%20int,%20int))
- Standalone open-source Android TTS engines such as `SherpaOnnxTtsEngine` (`com.k2fsa.sherpa.onnx.tts.engine`) expose `<action android:name="android.intent.action.TTS_SERVICE" />` and `<action android:name="android.speech.tts.engine.INSTALL_TTS_DATA" />` in their own APK manifest and execute in an isolated OS process over Android Binder IPC. The Free Software Foundation's GPL FAQ distinguishes separate programs communicating via IPC/system facilities from linked single-process derivatives. [SherpaOnnxTtsEngine manifest](https://github.com/k2-fsa/sherpa-onnx/blob/master/android/SherpaOnnxTtsEngine/app/src/main/AndroidManifest.xml), [GNU GPL FAQ: MereAggregation](https://www.gnu.org/licenses/gpl-faq.html#MereAggregation)

### Inferences

**Fix voice misranking with user choice rather than brittle heuristics.** `Narrator.initialize` currently forces any installed `en-GB` voice ahead of every `en-US` voice of equal reported `quality`, and resolves ties among same-quality voices in arbitrary `Set<Voice>` iteration order. Persist `selectedEnginePackage: String?` and `selectedVoiceName: String?` in `SharedPreferences("preferences", 0)` alongside `still`, list all offline English voices (`!isNetworkConnectionRequired && KEY_FEATURE_NOT_INSTALLED !in features`) grouped by accent (`UK`, `US`, `AU`, `IN`, other), and provide a `"Play sample"` button in `SettingsScreen` (`ui/Screens.kt`, lines 624–681). Retain the existing deterministic sort only as the initial default when no user preference is saved.

**Re-enumerate voices unconditionally on `onResume()`.** If `state.value.ready` is already `true` and the user visits system TTS settings to download a better local voice pack or switch system engines, `Narrator.refresh` (`Narrator.kt`, lines 156–162) currently ignores `onResume()` because of the `if (!state.value.ready && !initializing)` guard. Refreshing the available engine and voice catalog on `onResume()` (when not actively speaking) makes newly installed system voices appear immediately upon returning to AnchorReader.

**Eliminate inter-sentence pauses with `N+1` lookahead while keeping `ReaderViewModel` authoritative.** Switching blindly to `QUEUE_ADD` across whole pages complicates immediate pause, `setSentence(sentenceIndex - 1)`, recall-checkpoint navigation, and speed changes. Instead, keep `ReaderViewModel`'s one-sentence-at-a-time state machine intact (`MainActivity.kt`, lines 106–115; `ReaderViewModel.kt`, lines 178–189) and synthesize sentence `N+1` in the background via `synthesizeToFile` into `File(context.cacheDir, "tts_lookahead/")` while sentence `N` plays (or use a two-item `AudioTrack`/`MediaPlayer` double buffer). When sentence `N` completes, sentence `N+1` starts with near-zero latency; on pause, scrub, or speed change, discard the single cached lookahead file (`< 500 KB` WAV per sentence).

**Synchronize `SentenceDisplay.parts` opportunistically via `onRangeStart`.** `PlayerScreen.kt` (`FittedSentence`, lines 290–353) splits long sentences into visual `parts` (`Part 1 of K`) using `SentenceDisplay.kt`, requiring manual `Back`/`Next` taps while narration continues across the full sentence. Because `minSdk = 26` guarantees `onRangeStart(utteranceId, start, end, frame)` exists in bytecode, map character offset `start` (+ chunk offset from `SpeechBuffers.kt`) to the active part index and auto-advance `selectedPart` unless the user manually scrubbed parts during that sentence. Keep the manual `Back`/`Next` buttons visible because third-party engines are not required to emit `rangeStart` events (and `synthesizeToFile` playback does not emit live `onRangeStart` unless paired with engine/model duration metadata).

**Zero-risk path to GPLv3 engines.** Surfacing `getEngines()` in AnchorReader's settings immediately unlocks external open-source Android `TTS_SERVICE` apps (including `SherpaOnnxTtsEngine`, RHVoice, eSpeak NG, and community Piper Android wrappers) for users who install them separately, with zero binary size increase and zero copyleft contamination of AnchorReader's Apache-2.0 codebase.

### Gaps

Android does not expose human-friendly display labels inside `Voice.getName()` (names are opaque tokens such as `en-us-x-iob-local`); AnchorReader will need a clean formatting helper (locale + numbered voice label + sample button) rather than assuming `Voice.name` is readable prose. No measurement was taken of `com.google.android.tts` `onRangeStart` callback frequency across Samsung One UI, Pixel UI, and Xiaomi HyperOS builds.

## 2. Which open-weight on-device neural TTS models and runtimes fit AnchorReader?

### Takeaway

For bundled or in-app downloadable neural speech, choose **100% Apache-2.0 / MIT components** and avoid `espeak-ng` (`GPL-3.0`), `piper1-gpl` (`GPL-3.0`), Lessac-derived Piper voices (Blizzard 2013 non-commercial restriction), `KittenTTS 2` (Stellon Labs `< $1M` commercial cap), and autoregressive codec LLMs (`> 500 MB` weights, high RAM/thermal drain). Pair **Kokoro v1.0 (`Kokoro-82M` INT8, ~88–103 MB)** as the flagship Standard English Voice Pack with **KittenTTS v0.8 (`kitten-tts-nano-0.8-int8`, ~27.6 MB incl. 8 voices)** as the ultra-small Lite English Voice Pack, using an Apache-2.0 English IPA lexicon (`hexgrad/misaki` gold/silver dictionaries + deterministic rule fallback, zero `espeak-ng`). For the Android inference engine, either use **`com.microsoft.onnxruntime:onnxruntime-android:1.31.1`** from Maven Central (MIT, 16 KB ELF page-aligned, zero NDK in CI, **with its bundled `TelemetryInitializer` and `ACCESS_NETWORK_STATE` stripped via manifest merger**) or **`k2-fsa/sherpa-onnx` `v2.0.1`** (which became **100% Apache-2.0 and `espeak-ng`-free on 20 October 2026** via PR `#4055`, 16 KB ELF page-aligned, ready-made Kotlin TTS API, but distributed via GitHub Releases rather than Maven Central and requiring an explicit ProGuard `-keep` rule).

### Inferences

**How to solve the `espeak-ng` GPLv3 trap cleanly for both Kokoro and KittenTTS v0.8.** Both `Kokoro-82M` and `KittenTTS v0.8` consume the exact same 178-symbol IPA token table (`$` + punctuation + IPA letters/stress marks) and style vector slicing (`voice[tokenCount]` in Kokoro; `voice[min(text.length, 399)]` or phoneme-indexed prior in KittenTTS). In Python, many wrappers default to `phonemizer` + `espeak-ng` (`GPL-3.0`), which cannot be linked into AnchorReader's Apache-2.0 binary without copyleft obligations. Instead, use `hexgrad/misaki`'s `Apache-2.0` English dictionaries (`us_gold.json`, `us_silver.json`, `gb_gold.json`, `gb_silver.json`, ~340k entries total; ~`2.5–3.5 MB` when packed as a compressed binary DAWG/trie or plain UTF-8 lexicon) combined with deterministic Kotlin text normalization:
1. Expand numbers, years, ordinals, decimals, currencies (`$`, `£`, `€`), percentages, times, and common academic abbreviations (`Fig.`, `et al.`, `e.g.`, `i.e.`, `Dr.`, `pp.`, Roman numerals) before dictionary lookup.
2. Apply morphological suffix stripping (`-s`, `-ed`, `-ing`, `-ly`, `-er`, `-est`) against `us_gold` / `gb_gold` stems before falling back to `silver` ( mirroring `misaki`'s own Apache-2.0 `en.py` logic).
3. Handle true out-of-vocabulary words (rare proper nouns or technical neologisms in PDFs) with a compact Apache-2.0 grapheme-to-IPA rule/ONNX g2p fallback or spelled-acronym rule (all-caps 2–5 letter tokens without vowels -> letter names).

**Respect Kokoro's token-length "goldilocks window" (`100–200` tokens) and INT8 STFT precision.** `hexgrad/Kokoro-82M/VOICES.md` documents that Kokoro performs best between `100` and `200` phoneme tokens, warns against exceeding `~400` tokens (where speech rushes), and notes that very short inputs (`< 10–20` tokens, common on PDF chapter titles like `"1. Introduction"`) can sound clipped or faint. Two engineering rules follow:
1. Split long PDF sentences at clause boundaries (`;`, `—`, `:`, `,`) before phoneme count exceeds `320` tokens (replacing `SpeechBuffers.kt`'s `getMaxSpeechInputLength()` character splitter when neural narration is active).
2. Pad or punctuation-frame ultra-short headings (`< 15` phoneme tokens) or trim leading/trailing silence conservatively rather than feeding bare single-word tokens.
3. Prefer `onnx-community/Kokoro-82M-v1.0-ONNX`'s `model_quantized.onnx` (`88.08 MiB`) or `sherpa-onnx`'s hybrid INT8 export (`kokoro-int8-en-v0_19`, which keeps ISTFTNet conv layers in FP32 per `sherpa-onnx` PR `#4087` to avoid metallic vocoder ringing) — validate both on spoken technical prose before freezing the Voice Pack SHA-256.

**Strip ONNX Runtime's silent telemetry provider in `AndroidManifest.xml`.** Inspecting `onnxruntime-android-1.31.1.aar` revealed `ai.onnxruntime.TelemetryInitializer` registered as an automatic startup `ContentProvider` alongside `ACCESS_NETWORK_STATE`. Even though AnchorReader holds `INTERNET` only for optional user-initiated ChatGPT recall generation (and future explicit Voice Pack downloads), an automatic third-party startup telemetry initializer violates AnchorReader's strict local-first trust model (`"Device speech only"`). Merging `tools:node="remove"` on `ai.onnxruntime.TelemetryInitializer` and `android.permission.ACCESS_NETWORK_STATE`, plus calling `OrtEnvironment.getEnvironment(...).disableTelemetryEvents()`, eliminates all background telemetry at zero runtime cost.

**CPU execution provider over NNAPI on Android 15+.** Android 15 (API 35, AnchorReader's `targetSdk`) officially deprecated the Android Neural Networks API (`NNAPI`). Dynamic-length TTS graphs (`duration_predictor` + variable-frame ISTFT vocoder) frequently suffer graph-partition fallback overhead or FP16 precision glitches on OEM NNAPI drivers. Configure ONNX Runtime with the standard CPU Execution Provider + built-in XNNPACK intra-op acceleration on `2` to `4` threads (`OrtSession.SessionOptions.setIntraOpNumThreads`), running on `Dispatchers.Default` at background audio priority.

**Per-ABI APK splits protect GitHub Release download size.** Adding `onnxruntime-android` (`arm64-v8a` + `armeabi-v7a` + `x86_64`) increases a single fat universal APK from `26.4 MiB` to `~64 MiB`, whereas Google Play's `.aab` delivery adds only `~12.3 MiB` for `arm64-v8a` phones. Publishing per-ABI APKs (`arm64-v8a` APK `~38.7 MiB` alongside a universal fallback APK) in `.github/workflows/android.yml` keeps direct GitHub downloads lean while keeping `x86_64` available for `scripts/qa.sh` emulator runs.

### Gaps

No physical mid-range Android phone (for example Snapdragon 6 Gen 1, Tensor G2, or Cortex-A78/A55 big.LITTLE under thermal throttling with `workshop_background.mp4` decoding concurrently) was benchmarked in this session. Exact RTF, peak native heap (`OrtSession` arena allocator), battery drain over a 30-minute chapter, and perceptual audio difference between `onnx-community` `model_quantized.onnx` (`88.1 MiB`) and `sherpa-onnx` hybrid INT8 (`103.2 MB`) must be measured on hardware before locking the default Voice Pack manifest.

## 3. Do Android GenAI (`AICore`) or connected OpenAI endpoints change the local-first design?

### Takeaway

**No.** Reject cloud TTS and reject Google's new `com.google.mlkit:genai-text-to-speech` as primary narration backends. Google ML Kit GenAI TTS (`1.0.0-alpha1`, released October 2026) is an unstable Alpha governed by proprietary ML Kit Terms of Service, requires Google Play Services + AICore, fails on Android emulators and non-flagship phones (restricted to Pixel 8–11 and Galaxy S25/S26/Z8 lines), and breaks AnchorReader's Play-Services-free distribution on GitHub Releases. Meanwhile, OpenAI has **deprecated `tts-1`, `tts-1-hd`, and `gpt-4o-mini-tts` with a hard shutdown on 6 January 2027** (~9 weeks from this research date) in favor of stateful WebSocket/WebRTC `/v1/realtime` (`gpt-realtime-2.1-mini`), and AnchorReader's `ChatGptProvider` OAuth PKCE token (`chatgpt.tokens.use.direct`) is scoped to Codex `/v1/responses` text generation — not audio streaming — while cloud book narration would violate `Narrator.kt`'s offline privacy guarantee and rapidly exhaust user plan quotas.

### Cited Findings

- Google published `com.google.mlkit:genai-text-to-speech:1.0.0-alpha1` on Google's Maven repository (inspected POM and `1.0.0-alpha1.aar`, `minSdkVersion="26"`, docs updated `2026-10-27`). Its POM declares the proprietary **ML Kit Terms of Service** (`https://developers.google.com/ml-kit/terms`) and pulls transitive dependencies on `com.google.android.gms:play-services-base`, `play-services-tasks`, `com.google.mlkit:genai-common`, and `com.google.android.datatransport:transport-api`. [ML Kit GenAI TTS overview](https://developers.google.com/ml-kit/genai/text-to-speech), [Android guide](https://developers.google.com/ml-kit/genai/text-to-speech/android)
- Google's official ML Kit GenAI TTS documentation explicitly warns that the API is in **Alpha** (*"not subject to any SLA or deprecation policy and may receive backwards-incompatible changes"*) and restricts supported hardware to **Pixel 11, Pixel 10, Pixel 9, Pixel 8** series and **Samsung Galaxy S26, Galaxy S25, Galaxy Z Fold8, and Galaxy Z Flip8** devices with an updated Google Speech Recognition & Synthesis app (`com.google.android.tts`). On all other devices and emulators, `checkStatus()` returns `FeatureStatus.UNAVAILABLE` and `getSupportedVoices()` returns empty. [ML Kit GenAI TTS device list & troubleshooting](https://developers.google.com/ml-kit/genai/text-to-speech/android)

[OpenAI Deprecations](https://developers.openai.com/api/docs/deprecations), [OpenAI TTS guide](https://developers.openai.com/api/docs/guides/text-to-speech)

It calls only `GET /v1/models` and `POST /v1/responses` for short JSON-schema recall questions, and rejects accounts when `chatgpt.tokens.use.direct` is not granted (`ReaderViewModel.kt`, line 333).

### Inferences

**Do not build against an API shutting down on 6 January 2027 or pivot a book reader onto `/v1/realtime`.** Building HTTP `/v1/audio/speech` integration today would break in production within nine weeks, while migrating book narration to OpenAI's stateful WebSocket/WebRTC Realtime API (`gpt-realtime-2.1-mini`) would turn passive sentence reading into continuous bidirectional session management, require constant network connectivity, leak every sentence of the user's private PDF to a remote server (reversing `Narrator.kt`'s explicit `"Never sends book text to a network voice"` promise and `LegalDialog.kt`'s privacy summary), and burn user tokens at orders-of-magnitude higher volume than occasional three-question chapter recall checks.

**Why ML Kit GenAI TTS adds zero value over Phase 1 + Phase 2.** Flagship Pixel 8–11 and Galaxy S25–S26 devices already ship Google's latest local neural voices inside `com.google.android.tts`, which Phase 1's standard `android.speech.tts.TextToSpeech` voice picker accesses without adding Play Services, proprietary ML Kit terms, or Alpha SDK instability. Meanwhile, budget and mid-range phones (Pixel 6/7, Galaxy A-series, Motorola, Xiaomi/Redmi, OnePlus, GrapheneOS/LineageOS APK users) — the exact devices where built-in OEM TTS sounds worst — receive `FeatureStatus.UNAVAILABLE` from ML Kit GenAI TTS, whereas Phase 2's downloadable `Kokoro-82M` / `KittenTTS v0.8` ONNX packs work identically on every `arm64-v8a` / `armeabi-v7a` Android 8.0+ phone offline.

### Gaps

OpenAI's public Codex OAuth documentation does not publish an exhaustive endpoint allowlist for `chatgpt.tokens.use.direct`; no live token probe against `/v1/audio/speech` or `/v1/realtime` was performed because `tts-1`/`gpt-4o-mini-tts` deprecation and AnchorReader's local-only speech invariant independently rule out cloud narration.

## 4. What phased architecture should AnchorReader ship?

### Takeaway

Preserve `Narration` (`Narrator.kt`, lines 25–30) as AnchorReader's clean playback boundary and ship a **two-phase local-only architecture**:
- **Phase 1 (Immediate, `0 MB` APK delta, zero new dependencies):** Upgrade `Narrator` with engine + offline English voice enumeration/selection, sample preview, `ACTION_INSTALL_TTS_DATA` recovery, `synthesizeToFile` `N+1` lookahead buffering, and `onRangeStart` `SentenceDisplay.parts` sync.
- **Phase 2 (Opt-in downloadable Apache-2.0 Neural Voice Packs, offline-forever after download):** Add a `CompositeNarrator` routing between `SystemTtsBackend` (Phase 1) and `OnnxNeuralTtsBackend` (`onnxruntime-android:1.31.1` with telemetry stripped + Apache-2.0 `misaki` English IPA lexicon + `AudioTrack` `N+1` producer-consumer pipeline). Ship **zero neural weights inside the base APK**; let learners download verified **Lite (`KittenTTS nano-0.8-int8`, ~28 MB)** or **Standard (`Kokoro-82M` INT8, ~90–103 MB)** voice packs into `File(context.filesDir, "voices/")` with pinned SHA-256 verification, atomic file promotion, byte accounting in `SettingsScreen`, and one-tap deletion.

### Cited Findings

- `Narration` (`app/src/main/java/com/anchorreader/Narrator.kt`, lines 25–30) already isolates `ReaderApp` (`MainActivity.kt`) and `PlayerScreen.kt` from the underlying speech engine via a minimal contract: `state: StateFlow<VoiceState>`, `speak(text: String, onDone: () -> Unit)`, `pause()`, and `changeSpeed(): Float` (with `refresh(context)` and `close()` on `Narrator`).
- `PlayerScreen.kt` (`BackgroundVideo`, lines 193, 411–459) ties ambient video playback (`res/raw/workshop_background.mp4`) directly to `active && voice.playing`: pausing speech pauses the `MediaPlayer`, and `speak()`'s `onDone` callback in `MainActivity.kt` (lines 106–115) drives `model.nextSentence()` while keeping recall checks manual (`PlayerScreen.kt`, line 248).
- `SettingsScreen` (`app/src/main/java/com/anchorreader/ui/Screens.kt`, lines 624–681) already displays `storedBytes` (`Local storage`) computed via `ReaderViewModel.totalStoredBytes()` (`ReaderViewModel.kt`, line 140), and `LegalDialog.kt` + `docs/CREDITS.md` + `app/src/main/assets/legal/` enumerate every third-party license and network boundary (`ChatGptProvider` only when explicitly connected).
- GitHub Releases (`docs/RELEASES.md`) hosts AnchorReader's signed `.apk` and `.aab` artifacts directly under the repository (`https://github.com/chilliesdev/anchor-reader/releases`), providing a zero-backend static HTTPS host (or Hugging Face commit-pinned raw URLs) for versioned, immutable Voice Pack archives verified by in-app SHA-256 checksums.

#### Streaming, speed (`0.75x–2.0x`), pause/resume, and memory rules for Phase 2

1. **Sentence `N+1` producer-consumer pipeline:** A dedicated single-threaded synthesis coroutine (`Executors.newSingleThreadExecutor().asCoroutineDispatcher()`) synthesizes clause/sentence `N` into a `FloatArray`/`ShortArray` (`24 kHz` mono; a 12-second sentence is only `576 KB` in 16-bit PCM) and immediately begins synthesizing sentence `N+1` into a bounded `Channel(capacity = 1)` while `AudioTrack.write(..., WRITE_BLOCKING)` plays sentence `N`.
2. **Instant pause and zero-drift `ReaderViewModel` sync:** Calling `narrator.pause()` on pause, `setSentence(...)`, `nextSentence()`, concept swipe, or lifecycle `ON_STOP` cancels the synthesis job, calls `audioTrack.pause(); audioTrack.flush()`, and clears the `N+1` buffer immediately — preserving `BackgroundVideo`'s exact pause coupling.
3. **Speed control (`0.75x–2.0x`):** Pass clamped prosody speed (`0.85x–1.35x`) into Kokoro/KittenTTS's `speed` tensor input where natural phrasing benefits most, or apply `AudioTrack.setPlaybackParams(PlaybackParams().setSpeed(speed).setPitch(1.0f))` (API 23+, uses Android's built-in time-stretcher) so mid-sentence speed changes take effect immediately without re-running ONNX inference and without chipmunk pitch shift up to `2.0x`.
4. **Idle session eviction:** Unload `OrtSession` after `3` minutes of paused inactivity outside `PlayerScreen` (or on `ComponentCallbacks2.onTrimMemory(TRIM_MEMORY_UI_HIDDEN)`), freeing ~`100–160 MB` of native arena memory while the user browses the library or leaves the app backgrounded.
5. **Immutable Voice Pack integrity:** Pin a versioned JSON manifest in code (`packId`, `version`, `downloadUrl`, `sizeBytes`, `sha256`, `license`, `minAppVersion`). Download to `voices/<packId>.tmp`, verify SHA-256 before unpacking, write a `.verified` marker containing the digest, and atomically rename into `voices/<packId>/`. Never execute an unverified `.onnx` file.

Hosting ~`30–95 MB` Voice Pack archives on GitHub Releases assets vs pinned Hugging Face CDN URLs needs an operational decision on bandwidth limits and mirror fallback if Hugging Face is blocked on certain institutional/regional networks.
